# 选段翻译与 AI 伴读（R4 开发版）

这些功能已包含在 0.9.4；下方假服务步骤仅供开发验收。

## 选段翻译

在原文中选中文字，点击「翻译」或按 T。译文卡显示服务名，可复制译文，或创建高亮并把译文保存为批注说明。

模型地址、模型、凭据与「设置 → 翻译」及全文翻译共用；启用的术语表也随请求提供。没有配置时先去设置。选段翻译不会创建全文 PDF 翻译任务。

相同文字及配置在当前阅读器会话内复用成功结果；失败可重试。修改同一术语表的条目后，可关闭并重新打开阅读器刷新已有缓存。

## 问 AI

在右栏「AI」中输入问题；选中原文后点「问 AI」，会在输入框上方附上带页码的引用，可以移除。书桌「AI 伴读」也可选择文献后进入阅读器。

每篇文献首次发送前会列出发送范围和服务。只有点击「发送」才会调用模型；勾选「本文献不再提示」本身不会发送，会在发送时记住选择。服务或模型改变后重新确认。

上下文包含题名、摘要、本页文字、所选片段及最近对话，不自动检索整篇或调用文献操作工具。单段最多 8,000 字、问题 4,000 字；本页最多 20,000 字、摘要最多 6,000 字，最近最多 12 条历史且总计不超过 20,000 字。

回答逐步显示，规范的 `(p. N)` 页码可点击跳转。页码经过范围检查，但没有自动核验证据，请回原文确认。回答可保存为自由笔记并进入笔记空间，也可作为便签加入画布。

会话按文献保存在本机。AI 服务离线时，历史仍可查看；可以清空历史与记住的发送许可。停止生成的半截回答不会写入历史。

当前使用「设置 → AI 伴读」中的问答模型配置，支持 Python / OpenAI 兼容模式；FX Gateway 模式暂不走这条只读上下文对话路径。未运行本地 AI 服务时会显示灰色说明及设置入口。

## 本地假服务验收（由验收者执行）

默认离线预览没有启动 AI 服务，可以同时启用一个配置接口桩；它不会转发请求、不会使用真实模型，也不记录正文或凭据。

先由验收者重启预览，显式允许用户发起模型请求：

```bash
python3 ops/development/native_retain_preview.py restart --allow-external-models
```

然后从这次启动日志确定实际 AI 端口。默认是 41160；若出现
「AI 服务端口 41160 被占用，已切换到 41161」，则使用 41161。
**不要先启动假运行时再重启预览**，否则端口分配器会再次避开它。
确认该端口没有真实 AI 服务监听后，再启动假服务；下面的 41160 应替换为实际端口：

```bash
python3 ops/development/readflow_fake_openai.py --port 48991 --ai-runtime-port 41160
```

- 翻译设置：自定义 API；URL 为 `http://127.0.0.1:48991/v1`；模型 `readflow-test`；Key 填任意非空 ASCII 测试占位值，不填真实凭据；保存即可，不必检测。
- 配置接口桩已预置 AI 的同一假模型地址；也可在 AI 设置中选择 Python 模式、使用翻译配置并保存。若真实 AI 服务已正常运行，则省略 `--ai-runtime-port`，直接在该服务的设置中填写同一假模型配置。
- **模型请求**为 `POST http://127.0.0.1:48991/v1/chat/completions`。41160 只提供假 `/v1/runtime-config`，不是第二个模型服务。
- 选段翻译期望 `choices[0].message.content`；AI 使用 OpenAI SSE `choices[0].delta.content`，以 `finish_reason=stop` 和 `[DONE]` 结束。
- 假译文带「【译】」；假回答包含「这是假回答 (p. 2)」，分片发送。用两页以上 PDF 检查引用跳转、保存批注/笔记、加入画布。
- 关闭外部模型开关时，两种模型操作均拒绝；模型请求必须发生在点击翻译或确认发送之后。

如预览端口与默认值不同，配置接口桩端口需与预览的 AI 代理端口一致。不要将假服务绑定到正式应用使用的端口。
