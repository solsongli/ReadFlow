# ReadFlow 0.9.13

本版以论文译法一致性、可核对性和生成速度为重点。

- **论文术语表**：本地发现缩写定义、反复出现的术语、方法与模型名称。首次全文翻译时用一次小请求统一译法，模型名、数据集名与缩写保留英文，用户术语表优先。每批只发送相关术语。
- **上下文与格式**：续段及跨栏／跨页块带上前一块末句（最多 300 字符）；首次术语附英文，后文沿用译法；段首粗体小标题以受控结构保存，支持原位、原版式及重排版。
- **自动质检**：检查明显漏翻、引用、数字和百分比、占位符、长度及术语。不合格块最多严格重译一次；译文侧栏显示统计，支持全文「需核对」筛选。图内标签的质检也归入对应图表。
- **术语编辑**：侧栏保存修改后，可只重译相关块；不会静默改写全部已译文献。旧缓存可以通过「补翻／重新排版」准备术语，纯本地重新排版不调用模型。
- **并发**：DeepSeek 从 8 起步，连续成功后逐步升至 16，429 时全局减半；低于 8 的手动设置保持上限。CPU 推理仍限制两线程，AI 伴读和出题策略不变。
- **原版式加速**：先合成整页译文层再放回原页，避免按块重复扫描原页资源；字体流使用线性去重，避免全局重复对象比较。
- **按页增量**：补译只重绘变化页，复用其他页的内容和字体资源；保留原页树、内部链接、注释及 CropBox／旋转。重排 PDF 仍整体生成。
- **均衡密度**：默认尽量使用原字号，并在有空间时增大行距，最高约 1.5；可切回「紧凑」。修改后点「仅重新排版」应用，不产生模型费用。
- **导入后自动翻译**：默认关闭。开启后，工作台空闲时为新导入且有 PDF 的文献提交翻译；仍需配置服务并满足外部模型开关。明确提示 token 费用，可取消，旧库不批量回溯。

## 离线速度核对

相同假译文与原 PDF，在 CPU 上串行运行；X7 数字为上一版留存基准，本轮没有调用真实模型。

| 样例 | X7 全篇 | 本版全篇（均衡） | 本版单页补译 |
|---|---:|---:|---:|
| 矢量密集样例 `3.pdf`，30 页 | 190.232 秒 | 30.083 秒 | 1.013 秒，复用 29 页 |
| OpenVLA，37 页 | 8.158 秒 | 3.544 秒 | 0.348 秒，复用 36 页 |

性能剖析定位到逐块 `show_pdf_page` 的重复资源扫描，以及保存时全局去重；剖析器自身有明显开销，未用带剖析器的 565 秒作为提速对照。

## 质量工具与限制

- [离线质量核对](翻译质量核对.md)可读取已有译文缓存，统计引用／数字保留率、明显漏翻、术语一致率和长度比分布。
- 质检是启发式提示，不能判断论文结论、事实或全部专业语义。术语准备及一次严格重译会消耗额外 token；真实 DeepSeek 的准确度与端到端速度需另外验收。
- 不使已有译文缓存整体失效；旧译文不会自动补做所有质检。可通过术语编辑后的定向重译，或块卡片的重新翻译更新。
- 自动队列依赖工作台运行；关闭应用后未提交的队列不持久化，失败后需手动继续。纯文字条目与重复导入不会发起翻译。
- 扫描位图、不可编辑图内标签和不可靠区域仍可能保留原文；无足够空间的文字仍可能省略，块卡片保留全文。
- 线性保存可能比全局压缩产生稍大的 PDF；密集矢量样例约 17 MiB → 20 MiB，换取更快生成。增量只针对原版式，重排版仍需整体生成。

## X8b：翻译阶段提速返修（同版本重新打包）

- 修复每批保存后、每个块都重新读取整份 `translations.json` 的问题。现在一次读取后在内存汇总，避免数百到上千次 JSON 解析占住任务锁；新增读取次数回归。
- 主批次的合格块立即保存。不合格块进入同一并发池的小批重译队列（最多 4 块，另有 token 限额），与主批次交错执行；仍最多严格重译一次。响应截断后的拆批也进入调度队列。
- 精简提示词，移除空字段；章节共享、相同保留词只列一次，术语仅读取本批命中的部分。用实际请求估算合并过碎的小批，仍保留至少两波主批任务。术语、上下文、数字／引用／占位符质检和粗体格式要求全部保留。
- 新结果增加 `performance`：提取、术语、主批次、质检重译、渲染与缓存提交耗时；记录实际 HTTP 最大／平均并发、配置上限、批次计数、估算与服务返回的平均 token。主批次与重译的墙钟区间重叠，不能直接相加。
- 术语预处理仍先做一次，确保首批就使用统一译法。原版式与重排仍在翻译结束后生成，避免输出不完整快照；各批块译文可以先阅读。

### 延迟 fake 对比

每请求固定 1.5 秒，加每千输出字符 0.5 秒；使用验收 JSON 中的块长度与 29／42 次重译负荷，仅回放长度和判定分布，不访问模型、不用本次误报修正降低重试数量。没有重演旧缓存反复解析的 CPU 开销，也不包含提取与渲染。

| 论文 | 0.9.12 基线 | 原 X8 | X8b | 估算 prompt：基线／原 X8／X8b |
|---|---:|---:|---:|---:|
| OpenVLA | 15.233 秒 | 18.871 秒 | 13.312 秒 | 65,617／114,650／68,534 |
| SAM | 21.544 秒 | 28.814 秒 | 16.458 秒 | 92,628／152,593／91,559 |

SAM 为基线的 0.764 倍，达到不超过 1.2 倍的目标。估算 prompt 相比基线：OpenVLA +4.45%，SAM −1.15%，均在 +30% 内；这里不是 DeepSeek tokenizer 的精确计费值，真实用量由新计时字段记录并待验收。

回放中主批数量 OpenVLA 70→33、SAM 97→51；重译请求 29→17、42→19，最大实际并发均为 16。术语准备约 2.5 秒；首批译文仍需先等词表准备，保留一致性收益。
