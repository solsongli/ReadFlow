# ReadFlow 0.9.22

本版改善对照阅读「逐行对齐」译文的可读性，并收尾三个已知问题。

## 逐行对齐：字距恢复正常

0.9.21 的逐行对齐把每行中文两端撑满到英文行宽。同字号下，中文通常只占英文行宽的六成左右，结果不少段落字距接近一个字宽，疏密也因段而异。本版改为：

- 字号适度放大，最多为原字号的 1.12 倍，并且不超过行距；
- 每段取统一的较窄排版宽度，段内非末行两端对齐到这个宽度，字距增量不超过 0.12em。段落右侧留白，但字距正常、整齐；
- 中文足够长、能自然填满时，仍对齐到原行宽。

第 i 行中文仍落在英文第 i 行的同一高度。离线四篇论文、983 个块的结果：

| 指标 | 0.9.21 | 0.9.22 |
| --- | --- | --- |
| 字距增量 P50 / P95 / 最大值 | 0.41 / 1.10 / 90.2 em | 0.12 / 0.12 / 0.12 em |
| 基线偏差 P95 | 0 pt | 0 pt |
| 行数与原文一致 | 98.07% | 98.17% |
| 缩小字号的块 | 170 | 168 |
| 需要多一行的块 | 18 | 17 |
| 平均填充率 | 88.8% | 82.4% |

逐行版中的段首小标题（如「任务。」「相关任务。」）现在显示为粗体。

## 其他修正

- **批注**：选中文字创建批注后，立即清除选区并收起选中文字工具条。宽窗口焦点落在页边说明框，窄窗口仍用页内编辑框，与 Zotero 一致。
- **段首粗体**：较早译文缓存中缺少粗体标记的段首小标题（如 SAM 的 “Task.”、“Pre-training.”），现在根据原文字体边界与中英文标点在本地恢复。四篇论文共恢复 107 块；不改缓存，不调用模型。
- **测试**：三个仍在等待旧版阅读器的界面冒烟脚本已改为面向原生阅读器。新增 `npm --prefix frontend/web run smoke`，串行运行全部冒烟脚本。

本版不新增依赖、模型或网络访问。
