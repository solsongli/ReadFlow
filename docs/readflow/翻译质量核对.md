# 翻译质量的离线核对

这个工具只统计已有译文，不发送任何模型请求，也不会修改原缓存。结果用于定位问题，不能替代专业校对。

在仓库根运行，`<Python>` 可使用本地内置运行时的 Python；无须安装依赖：

```bash
PYTHONPATH=. <Python> -m ops.development.paper_blocks_corpus \
  --quality-blocks /path/to/blocks.json \
  --translations /path/to/translations.json \
  --language zh-CN \
  --fingerprint <服务指纹> \
  --terms-file /path/to/terms.json \
  --output /tmp/readflow-quality
```

- 服务指纹是同目录 `selection.json` 或 `result.json` 中的 `fingerprint`，不是 API Key；不要把 Key 传给本工具。
- `--terms-file` 可省略。存在用户术语表时，可另外用 `--user-terms /path/to/exported-glossary.json` 传入导出的 JSON；用户译法优先。
- 只读取明确指定的 JSON，不扫描配置或凭据目录；符号链接会被拒绝。无需启动 ReadFlow 或假模型服务。
- 输出为 `quality.json`：匹配缓存块数、引用／数字多重集合保留率、明显漏翻比例、术语出现次数及标准译法命中率、长度比 P10／P50／P90，以及逐块需核对原因。
- 分母为零时比例是 `null`。如果匹配块数为零，应先检查语言、服务指纹和块版本，不能据此认定译文没有问题。
- 占位符在成功译文缓存中已还原，因此离线报告不推测历史占位符是否丢失；在线质检在还原时检查。

比较改进前后时，对两份译文缓存使用同一份块数据、目标语言及有效术语表，分别输出目录。不要把不同服务／语言的缓存混成一个分母。

## 本地 fake 验收

现有 `ops/development/readflow_fake_openai.py` 继续只监听回环地址，不访问上游。以下模型名用于确定性故障场景：

- `readflow-qa-untranslated`：首轮保留英文，严格重译后返回示例中文。
- `readflow-qa-citation`：首轮丢失保护片段，严格重译后恢复。
- `readflow-qa-terms`：首轮违反术语，严格重译后采用指定译法。

这些输出只证明流程与统计，不代表真实模型的翻译质量。普通 `readflow-test` 仍是前缀回显，可能被正确标记为漏翻。

## X8b 耗时与失败复核

新任务的 `result.json.performance` 包含：

- `timings_s.extraction`、`terminology`、`main_batches_wall`、`qa_retranslation_wall`、`render`；另有 `translation` 总窗口与 `cache_commit`。
- `requests.max_concurrency`／`mean_concurrency`：从首个 HTTP 请求至最后响应的实际在途请求时间积分，等待并发许可和退避不记作在途。
- `batches` 分术语、主批和重译：`count`、`mean_prompt_tokens`、`mean_completion_tokens`、`mean_estimated_prompt_tokens`、`usage_responses`。实际值来自服务；估算值仅用于调度。缺失用量时应看覆盖数。
- 主批与重译流水并行，两段墙钟时间不能相加；排版在翻译结束后运行。配置与池上限在 `policy`，不等同实际达到的并发。

只读复核历史警告：

```bash
PYTHONPATH=. <Python> -m ops.development.translation_retry_audit \
  --directory /path/to/paper-blocks/<sha256> \
  --output /tmp/readflow-retry-audit.json
```

只读取该目录的 `blocks.json`、`translations.json`、`result.json`、`terms.json`，不改缓存。数字等价写法与结构化脚注的口径已改进；前后译文必须用同一规则重算。

延迟回归使用 `backend.library_mvp.tests.benchmark_translation_pipeline`；`--directory` 同上，`--output` 指定报告，省略目录则用合成数据。默认真实等待 1.5 秒＋每千输出字符 0.5 秒，`--scale` 可缩短单测等待。请求由进程内 mock 处理，不连接服务。它回放既有输出长度与 QA 分布来测试调度，不测试模型语义准确度。

CI 的合成延迟回归在 `test_translation_pipeline` 中；本地可显式设置 `READFLOW_TRANSLATION_BENCH_DIR` 为获准读取的 SAM JSON 目录，再运行该模块的 `test_sam_json_delay_and_prompt_limits`。语料不随仓库提交，缺少显式目录时此项会说明原因并跳过。
